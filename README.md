# HELLSPRESSO — 1단계 / 0.1.0

개발 명의: **SλVE POINT**. PC 브라우저용 싱글플레이 FPS의 첫 구현 단계다.

## 실행

Node.js **24.22.1**에서 검증했다. Node 24를 설치한 뒤 이 파일이 있는 폴더에서 실행한다.

```bash
npm ci
npm run dev
```

터미널에 표시된 `http://127.0.0.1:5173`을 PC 브라우저에서 연다. 새 게임을 클릭하면 포인터 락을 요청한다. 브라우저가 거절하면 정지 화면의 계속하기를 다시 클릭한다. ESC 이후에는 브라우저 정책에 따라 새 클릭이 필요할 수 있다.

```bash
npm test
npm run build
npm run preview
```

빌드 결과는 `dist/`다. 파일 탐색기에서 index.html을 직접 여는 방식은 ES 모듈 로딩 정책 때문에 지원하지 않는다. 로컬 HTTP 주소나 정적 호스팅을 사용한다.

## 구현 범위

- 프로시저럴 3D 이동 구역, 커터칼 임시 메시, 외부 모델/오디오/이미지 파일 없음.
- WASD 이동, Shift 달리기, F 대시, C/Ctrl 슬라이딩, 2단 점프.
- 직립 AABB와 정적 AABB의 연속 sweep, 벽 충돌, 단차, 낮은 천장에서 기립 방지.
- 고정 60Hz 시뮬레이션, 프레임 지연 잔여 시간 보존, 프레임당 계산 상한.
- HP/CAF/스태미나, 독립·동시 사망 원인, 오버차지 공통 clamp.
- 메뉴, 정지, 인벤토리 빈 화면, HUD, 그래픽/마우스/키 설정, 설정 로컬 유지.
- ESC·락 상실·포커스 상실·탭 숨김 시 정지. 인벤토리는 시간이 계속 흐른다.
- `?debug=1`에서 분당 CAF 소비/수지와 동작 상태 표시.

**현재는 1단계다.** 무기 공격·적·추출·회복·제작·신성지대·게임 진행 저장·Firebase 로그인·3개 스테이지·보스·음향은 후속 단계다. 무기 메시만으로 공격이 구현됐다고 취급하지 않는다. 현재 보충 수단은 없으므로 기본 CAF100은 플레이 시간50초에 고갈된다. 사망 뒤 새 게임으로 재시작한다.

환경 설정이 없어도 게스트 모드로 시작한다. `.env.example`은 4단계 Firebase 연결용 공개 설정 서식이다. 1단계에는 Firebase SDK와 네트워크 쓰기가 없다. 관리자 키나 서비스 계정 키를 추가하지 않는다.

## 조작

| 입력 | 동작 |
|---|---|
| WASD / 마우스 | 이동 / 시점 |
| Shift | 달리기 |
| F | 대시, 스태미나10 |
| C / Ctrl | 지상 슬라이드, 스태미나15 |
| Space 두 번 | 점프·공중 점프 |
| Tab | 인벤토리. CAF 감소 지속 |
| H | 빠른 HP 회복 예약키. 현재 소지품 없음 |
| X | 추출기 예약 동작. 현재 재료 없음 |
| ESC | 락 해제·일시정지 |

H와 ESC는 예약키다. 나머지는 설정의 조작법에서 변경한다. 대시의 기본값은 F이며 Q/Alt는 사용하지 않는다. Ctrl+W 같은 브라우저 단축키를 완전히 차단할 수 없으므로 슬라이딩은 C를 권장한다. 우측 낮은 통로는 슬라이드, 중앙 단차는 걷기/점프로 검증할 수 있다.

## 확정 규칙과 임시값

확정 규칙은 `src/config/rules.ts`, 미확정 기본값은 `src/config/tunables.ts`다. 임시값마다 `// TBD: 기획 미확정`을 붙였다. 0단계의 제안을 확정된 설정으로 승격하지 않았다.

물리를 직접 구현한 이유: 정적 바닥·벽·발판 중심 공간을 작은 의존성으로 만들고 sweep 충돌을 순수 로직으로 검증하기 위해서다. 0단계 캡슐 제안 대신 **직립 AABB**를 사용했다. 캡슐 충돌이나 Rapier를 구현했다고 주장하지 않는다.

## 선택 브라우저 QA

게임 의존성을 줄이기 위해 Playwright는 필수 패키지에 포함하지 않았다. 자동 브라우저 QA를 재현하려면 별도 설치한다.

```bash
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install chromium
node scripts/browser-smoke.mjs
npm run build
node scripts/production-smoke.mjs
```

`browser-smoke.mjs`는 개발 서버를 직접 열고 닫는다. 실제50초 CAF 사망도 기다린다. `production-smoke.mjs`는 빌드된 dist를 검증한다. headless 마우스 델타가 상쇄되면 상대 mousemove 이벤트 주입으로 처리·렌더 경로를 따로 검사하고 실제 마우스 경로는 미검증으로 표시한다. 실제 운영체제 마우스와 Alt+Tab은 직접 확인해야 한다. 다른 Chromium 실행 파일은 `BROWSER_EXECUTABLE`, 별도로 설치한 Playwright 모듈은 `PLAYWRIGHT_MODULE`로 지정할 수 있다. 게임 런타임에는 이 도구가 필요 없다.

개발 모드의 `?debug=1`에서만 브라우저 QA용 스냅샷/자원 주입 인터페이스가 노출된다. production 빌드에는 이 인터페이스가 없다. 실제 플레이 경로로 주입 기능을 제공하지 않는다.

## 산출물과 다음 단계

`docs/STAGE_1.md`에 확정 수치 대조, QA 판정, 엣지 케이스와 미검증 항목을 기록했다. 전체 파일 전문은 ZIP 최상위의 `HELLSPRESSO_Stage_1_Full_Source.md`에 있다. `package-lock.json`을 포함하며 축약하지 않는다. ZIP에는 실행 가능한 `dist/`도 포함한다.

자동 브라우저 QA에서 네이티브 포인터 이동은 실행 환경의 재중앙화 이벤트와 상쇄되었다. 시점 입력 처리와 실제 화면 변화는 합성 DOM 마우스 이벤트로 확인했으며, 물리 마우스·일반 창 모드 브라우저의 시점 조작은 별도 확인이 필요하다. ESC 후 클릭으로 마우스 잠금을 재개하는 경로는 통과했다.

Firebase 설정은 4단계, Render/GitHub 배포 절차는 7단계에서 진행한다. 1단계만으로 완성 데모나25~40분 분량을 제공한다고 주장하지 않는다.
